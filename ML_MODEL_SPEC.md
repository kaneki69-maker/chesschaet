# Модель распознавания фигур (3.0.0)

## Контракт
| Параметр | Значение |
|---|---|
| Файл | `app/src/main/assets/piece_cnn.bin` (174 736 байт, sha256 в `ml/results/piece_cnn.sha256`) |
| Формат | `CCNN`, int32 version=1, int32 layers=5, затем float32 w,b по слоям (little endian) |
| Вход | 4×32×32 float32 на клетку: 3 канала (пиксель − медиана рамки клетки)/255·2 ∈[−1,1] + абсолютная яркость |
| Архитектура | conv3×3(4→12)+ReLU+pool → conv(12→24)+ReLU+pool → conv(24→32)+ReLU+pool → dense 512→64 ReLU → dense 64→13 |
| Выход | 13 логитов: `empty, P, N, B, R, Q, K, p, n, b, r, q, k` |
| Порог | softmax ≥ 0.70, иначе клетка «не прочитана» |

Клетка вырезается из найденной доски билинейно с внутренним отступом 6 %. Kotlin-код извлечения признаков и сети сверен с NumPy-эталоном (`PieceNetParityTest`: расхождение признаков < 1e-4, логитов < 1e-2, классы совпадают).

## Данные и обучение
Реальных размеченных скриншотов шахматных клиентов в среде не было, сети не было, поэтому набор **синтезирован** (`ml/synth.py`, `ml/gen_dataset.py`, воспроизводим по seed): случайные темы досок, текстуры, подсветка последнего хода, точки возможных ходов, координаты, шумы/размытие/JPEG-подобные артефакты, сдвиг и масштаб, случайные расстановки; фигуры рисуются 7 наборами глифов (DejaVu Sans, DejaVu Sans Bold, FreeSerif, FreeMono, Unifont, Font Awesome solid, Material icons).  
Обучение: 192 000 клеток (train), 12 800 (val), 44 800 (test, отдельные seed), NumPy-реализация сети (Adam, косинусный lr, label smoothing 0.05, dropout 0.25, гауссов шум 0.02 на признаках; аугментации — при генерации данных), 6 эпох на CPU.

## Результаты (test, 44 800 клеток / 700 досок)
| Модель | Точность по клеткам | Доски без единой ошибки | Путаницы цвета |
|---|---|---|---|
| Поставляемая (все стили в обучении) | 99.978 % | 98.57 % (argmax, без порога) | 1 |
| Контроль: стиль `freeserif` исключён из обучения | 99.96 % всего; **99.93 % на невиданном стиле** | 97.57 % | 1 |

С порогом 0.70 (как в приложении) принято 99.63 % клеток, из принятых верны 100 % на этом тесте; остальные помечаются как неуверенные. Ошибка «пустая клетка ↔ фигура»: 0 на тесте. Подробности по классам и стилям: `ml/results/*.json`.

Сквозная проверка на 16 отрисованных «скриншотах телефона» из двух последовательных легальных партий (белые снизу и чёрные снизу; другие seed, темы и позиции, чем в обучении): найдена доска с точностью до 1 %, верно 1024/1024 клеток, все ходы отслежены.

## Ограничения (честно)
* **Тест — синтетика того же генератора.** Контрольный «невиданный» стиль — другой шрифт того же семейства глифов, а не другая художественная отрисовка. Реальные наборы фигур chess.com/lichess/другие (иные силуэты, тени, 3D-стили, анимации, перспектива, полупрозрачные оверлеи) **не проверялись**; точность там неизвестна и вероятно ниже. Для оценки нужны реальные размеченные скриншоты.
* Доска должна быть осевой (без поворота/перспективы), квадратной, 8×8, в видимой области.
* Одна ошибка в клетке меняет FEN — всегда сверяйте позицию в экране сканирования.
* Формат TFLite не используется: в среде не было TensorFlow-конвертера; веса хранятся в собственном компактном формате.
